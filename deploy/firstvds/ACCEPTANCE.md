процессы Caddy, MediaMTX и ffmpeg после остановки отсутствовали.

На FirstVDS из Caddy удалён `trusted_proxies 89.19.211.4`, а в Compose игры
восстановлен `TRUSTED_PROXY_IPS=172.31.67.2`. Caddy прошёл validate/reload.
Игра пересоздана с тем же проверенным image ID после drain и проверки rooms=0.
Прямые HTTPS smoke и четыре HTTPS/WSS клиента прошли повторно; Origin и release
SHA проверены. Игра больше не зависит от старого VPS.

Первый повторный smoke с Mac/Docker завершился `fetch failed`/`ECONNRESET` до
TLS-handshake на обычном сетевом маршруте. Прямой curl через `--interface en0`
и запрос с другого VPS прошли. Smoke и четыре SDK-клиента затем прошли через
одноразовый localhost TCP relay, привязанный к en0 и 82.146.39.112:443, с SNI

## История: временный HTTPS bridge и завершение DNS

При первом запуске REG.RU был недоступен и оператору, и владельцу, поэтому
потребовался временный proxy. 19.10.2026 в 11:56 (Asia/Yekaterinburg) в REG.RU
сохранено изменение **только A `67`: 89.19.211.4 → 82.146.39.112**. Остальные
ресурсные записи, NS, TTL и SOA не изменены. Результат подтверждён в панели.

До изменения оба авторитетных NS отдавали A 89.19.211.4 с TTL 86400 секунд.
Первые проверки после сохранения, в том числе TCP dig с флагом AA, ещё отдавали
старый IP: публикация зоны провайдером не мгновенная. По
[документации REG.RU](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/nastroyka-resursnykh-zapisey-v-lichnom-kabinete)
обновление зоны занимает 15–60 минут; затем отдельно истекают старые DNS-кэши.
Публикация на NS не считается подтверждённой только по скриншоту панели.
19.10.2026 в 12:04:06 (Asia/Yekaterinburg) оба NS по TCP вернули AA-ответ
`67.jeshio.ru A 82.146.39.112`. Публикация нового адреса подтверждена. Старый
proxy сохраняется **как минимум до 20.10.2026 12:05 (Asia/Yekaterinburg)**,
затем отдельно проверяются старые активные соединения/трафик.

Прямой HTTPS нового IP с проверкой сертификата и публичный `/ready` по-прежнему
подтверждают release `706455e57c51019f33c6455d4cf573f4ed65392e`, dirty=false.
После DNS-перехода четыре SDK-клиента повторно прошли HTTPS/WSS, одну общую
комнату и Origin-проверку **напрямую на 82.146.39.112**: изолированный read-only
Node-контейнер задавал только для себя `67.jeshio.ru → 82.146.39.112` через
`--add-host`, сохраняя проверку TLS. DNS Mac и серверов этим не изменялся.
Старый `roma67-https.service` остаётся
enabled/active и проксирует **HTTPS с проверкой сертификата** на 82.146.39.112,
Host/TLS server name `67.jeshio.ru`. Legacy IP перенаправляет на домен.
`roma67-game.service` inactive/disabled, зависимость Wants/After из HTTPS unit
удалена. Две группы комнат не создаются.

Только proxy игры на новом Caddy временно доверяет 89.19.211.4. Серверный Compose
игры временно задаёт `TRUSTED_PROXY_IPS=172.31.67.2,89.19.211.4`: это сохраняет
реальный client IP в цепочке, не доверяя присланному клиентом X-Forwarded-For.
Старый proxy перезаписывает этот заголовок адресом непосредственного клиента.
Доверие остальных проектов не изменено. Исходный direct Compose сохранён в
`/opt/operation-67/operator/compose-direct.yaml`.

Завершение перехода:

1. A `67` сохранена в панели и подтверждена на обоих авторитетных NS. Команды
   повторной проверки: `dig +tcp @ns1.reg.ru 67.jeshio.ru A` и
   `dig +tcp @ns2.reg.ru 67.jeshio.ru A`. Момент начала TTL-hold указан выше.
2. Проверить авторитетный DNS, HTTPS/WSS, exact release и браузерный UI напрямую.
3. Сохранять старый proxy минимум **86400 секунд после подтверждения обоих NS**.
   После этого проверить отсутствие старого трафика/активных соединений и
   отключить только `roma67-https.service`. Старый VPS ещё содержит радиорелей —
   не удалять его.
4. Удалить `trusted_proxies 89.19.211.4` из `/opt/infra/sites/operation67.caddy`,
   validate/reload Caddy. При следующем безопасном обновлении игры, после drain
   и rooms=0, вернуть TRUSTED_PROXY_IPS к `172.31.67.2` и проверить readiness.
5. Проверить автоматическое управление/renewal TLS нового Caddy. Пока DNS старый,
   новая ACME challenge может не пройти; до 12.12.2026 переход должен завершиться.
