# Размещение на 89.19.211.4

Сайт: **https://67.jeshio.ru/**. Прежний адрес **https://89.19.211.4/** сохранён. Новая сборка использует Colyseus: HTTPS-вход и WSS комнат, прямой WebRTC по возможности. Старый протокол `/ws` несовместим с новой сборкой.

Это отдельная установка: `/opt/roma-operation-67`. Здесь находятся готовая игра, серверные зависимости Colyseus и Express, переносимый Caddy, конфигурация, сертификаты и журналы. Node.js используется уже установленный, глобальные пакеты и Docker не устанавливаются. Установка добавляет пользователя без входа `roma67` и две службы `roma67-game` / `roma67-https`.

Обычный HTTP остаётся закрыт. Добавляется только правило UFW для TCP 443 на IP 89.19.211.4 с комментарием `roma-operation-67 HTTPS`. Приложение слушает только 127.0.0.1:5179. HTTPS получает и обновляет сертификат поддомена и короткоживущий сертификат IP через Let's Encrypt, проверка идёт по TLS-ALPN на 443. Сертификаты хранятся внутри `data`; существующие настройки nginx, прокси и MediaMTX не меняются.

Текущий лимит основного сайта — **64 комнаты / 256 мест**, установлен 16 сентября 2026 по запросу владельца при выпуске Colyseus. Нагрузочная вместимость 64 комнат не подтверждена (см. `QA-colyseus.md`). Процесс игры — максимум 512 МБ памяти и 60% одного ядра; HTTPS — 192 МБ и 20%. Службы запускаются автоматически после перезагрузки. Начальный установщик по-прежнему использует 4 комнаты; текущий лимит задаёт `/etc/systemd/system/roma67-game.service.d/90-room-limit.conf`.

## Остановить и включить снова

Через SSH:

```sh
sudo systemctl stop roma67-https roma67-game
sudo systemctl start roma67-game roma67-https
```

Остановка освобождает процессор, комнаты завершаются. Файлы и сертификаты сохраняются.

## Полностью удалить игру

```sh
sudo rm -f /etc/systemd/system/roma67-game.service.d/90-room-limit.conf
sudo /opt/roma-operation-67/uninstall.sh --remove
```

Команда останавливает игру, выключает автозапуск, удаляет обе службы, добавленное правило HTTPS, пользователя `roma67` и папку игры с сертификатами и журналами. Другие службы и правила не удаляются. Если системные файлы установки были вручную изменены, скрипт остановится перед удалением для проверки. Серверные комнаты хранятся только в памяти; рекорды и настройки в браузерах игроков остаются.

Без `--remove` скрипт только показывает инструкцию. Локальная папка исходников на Mac не удаляется. Для повторного размещения исходники и эти инструкции сохранены в проекте.

## Проверка и обслуживание

```sh
sudo systemctl status roma67-game roma67-https
curl --fail https://89.19.211.4/health
sudo tail -40 /opt/roma-operation-67/logs/https.log
```

Не публикуйте содержимое `data`: там лежат приватные ключи сертификатов. Версия Caddy закреплена на 2.11.4, архив проверен по SHA-256 из официального релиза. Перезапуск игры завершает активные бои.

Для обновления готовые `dist/` и `dist-server/` собираются на Mac и заменяются при остановленной `roma67-game`; `data`, `.managed-by`, `.firewall-created`, пользователь и службы сохраняются. Начальный `install.sh` специально отказывается перезаписывать существующую установку.

## Выпуск Colyseus и возврат

Нужен Node.js 22.12+ (на этом VPS проверен 22.23.1). Клиент и сервер меняются одним выпуском. Открытым старым вкладкам потребуется перезагрузка; локальные имена, облики, настройки и рекорды сохраняются.

На рабочем компьютере:

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm package:vps test-artifacts/roma67-colyseus-runtime.tar.gz
scp test-artifacts/roma67-colyseus-runtime.tar.gz deploy/vps/release.sh jeshio@89.19.211.4:/tmp/
```

После завершения испытаний, когда комнаты пусты:

```sh
ssh jeshio@89.19.211.4
sudo bash /tmp/release.sh deploy /tmp/roma67-colyseus-runtime.tar.gz 64
```

Скрипт проверяет установку и зависимости, дважды проверяет нулевое число комнат, сохраняет `dist`, `dist-server`, `node_modules`, `package.json` и переопределение лимита комнат, останавливает игровую службу и заменяет весь комплект. Необязательное последнее число задаёт лимит от 1 до 64; без него настройка не меняется. При провале проверки работоспособности автоматически возвращаются файлы и прежний лимит. Явный откат также восстанавливает лимит из новых резервных копий. Между последней проверкой и остановкой остаётся короткое окно гонки: первый выпуск старого сервера не поддерживает режим запрета новых входов. Обновляйте в тихое время. HTTPS и настройки ресурсов сохраняются.

Для ручного возврата используйте **точный путь**, напечатанный скриптом выпуска:

```sh
sudo bash /tmp/release.sh rollback /opt/roma-operation-67/backups/colyseus-ДАТА
```

Возврат тоже требует пустых комнат и создаёт резервную копию снимаемой версии. Скрипт принимает только собственные копии с `release.json`; для старых архивов из истории ниже нужен ручной разбор их состава.

### Отдельный интернет-стенд

`staging.sh up RUNTIME QA_CLIENT` запускает временную службу `roma67-qa` на 5209 с лимитами 512 МБ / 60% ядра и добавляет HTTPS-маршрут `/qa-colyseus/`. Текущий сайт остаётся на 5179. `staging.sh down` убирает только этот маршрут и останавливает стенд. Временная служба ограничена двумя часами; перед длительной ручной проверкой перезапустите её.

QA-клиент собирается отдельно:

```sh
VITE_SERVER_URL=https://67.jeshio.ru/qa-colyseus pnpm exec vite build --config vite.qa.config.ts --base=/qa-colyseus/ --outDir=test-artifacts/qa-internet
tar -czf test-artifacts/roma67-qa-client.tar.gz -C test-artifacts/qa-internet .
```

Адрес: `https://67.jeshio.ru/qa-colyseus/?qa&guest=1`. Панель четырёх клиентов: `/qa-colyseus/qa-panel.html`. `/api/qa` и управление тестовым боем входят только в QA-стенд. В основной выпуск их не включать.
