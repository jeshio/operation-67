# Ограниченный запуск Codex и Claude Code

AGENTS.md содержит общие инструкции, CLAUDE.md импортирует `@AGENTS.md`. Это инструкции модели; они не являются техническим sandbox и не могут гарантировать запрет чтения/записи. Реальные границы устанавливаются средой запуска, файловыми правами, сетью и approvals. Активные `.codex`/`.claude` settings и hooks этим этапом не создавались и не проверялись. Глобальные настройки не читались.

Проверенные при планировании версии: Codex CLI 0.145.0, Claude Code 2.1.220. Опции меняются; перед настройкой сверять локальный `--help` и официальную документацию. [Разрешения Codex](https://learn.chatgpt.com/docs/agent-approvals-security), [справочник настроек](https://learn.chatgpt.com/docs/config-file/config-reference).

Для Codex запускать из каталога проекта с sandbox `workspace-write` и approval policy `on-request`, например:

```sh
codex -C /Users/jeshio/dev/operation-67 --sandbox workspace-write --ask-for-approval on-request
```

Не использовать режим отключения sandbox/approvals. Workspace-write не означает полный запрет чтения вне проекта: это дополнительно ограничивает среда/ОС. В этой задаче запись была разрешена только внутри проекта и служебных временных каталогов среды, но рабочие артефакты создавались в игнорируемых каталогах проекта.

Для Claude Code — запуск из этого каталога с обычными разрешениями (`claude --permission-mode default` после сверки `--help`), без bypass/skip-permissions. Не добавлять домашний каталог или соседние проекты в разрешённые roots. Не считать неподтверждённые локальные или глобальные правила автоматически действующими. Для надёжной изоляции использовать отдельную среду с минимальными правами.

Runtime 24 можно установить через локальный менеджер версий или распаковать официальный Node в `.tools/`, сверив SHA-256 с официальным SHASUMS256. Не обновлять глобальную систему ради задачи. Затем добавить bin выбранного runtime в PATH текущего процесса. `.nvmrc` и `packageManager` фиксируют версии. Новые npm-зависимости для защиты не добавлялись.

Сеть открывать точечно для официальных Node/npm/GitHub release/advisory и используемых Docker registries. Audit отправляет сведения о зависимостях; Gitleaks и Semgrep работают локально, Semgrep container — с network=none и metrics=off. Playwright использует отдельные временные контексты без личного профиля браузера. Не разрешать agent shell доступ к Docker socket на реальном production; локальные контейнерные тесты — отдельная ограниченная операция.
