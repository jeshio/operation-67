# Контракт приложения для сервера

## Runtime и запуск

Рекомендован Node.js 24.21.0 LTS, pnpm 10.33.2 только при сборке. Пакет декларирует Node ^22.12.0 или ^24.0.0; проверяемый release-путь использует 24. Существующий Node 20 не подходит. Архив собирается на Linux для архитектуры VPS, запускается без исходников, Git и package manager: `node dist-server/index.js` из корня распакованного комплекта, от непривилегированного пользователя. Python 3.11+ нужен доверенному операторскому валидатору архива, приложению он не нужен.

Основной процесс один. Горизонтальное масштабирование/кластеризация не настроены: комнаты и гостевые ключи локальны процессу. БД, миграций и процедур отката данных нет. Рестарт теряет комнаты; браузерные сохранения остаются на устройствах игроков.

| Переменная | Значение/правило |
|---|---|
| NODE_ENV | `production` на сервере |
| HOST | `127.0.0.1` под локальным reverse proxy; `0.0.0.0` в изолированной Docker-сети |
| PORT | 5179, снаружи доступен только HTTPS reverse proxy |
| ALLOWED_ORIGINS | Обязательный список точных HTTPS origins через запятую, без `/`, wildcard и путей |
| TRUSTED_PROXY_IPS | По умолчанию пусто; точные адреса непосредственных доверенных прокси, без CIDR/wildcard |
| MAX_ROOMS | По умолчанию 4, production максимум 64; повышение только после capacity-проверки VPS |
| GAME_QA | Не устанавливать в `1` в production — запуск будет отвергнут |
| RELEASE_COMMIT / RELEASE_DIRTY | Только входы Docker build; runtime не может ими заменить встроенный SHA |
| GAME_DOMAIN | Только compose/Caddy; публичный DNS origin |
| PUBLIC_ORIGIN | Только операторский release.sh; явный HTTPS origin для проверки результата |

Приложение самостоятельно `.env` не читает. Переменные задаёт systemd/compose. В production нет секретов приложения; если инфраструктурные секреты появятся, хранить вне артефактов и репозитория. Запрещено встраивать секреты в `VITE_*`.

## Сеть

`POST /api/join` — единственная публичная выдача резерваций; JSON до 4096 байт. Colyseus WebSocket подключается по уже выданной резервации. `/matchmake*` и внутренние `/__*` закрыты. Переподключение и замена вкладки проходят через `/api/join`. Native-запросы без Origin разрешены; Origin является браузерной защитой, не паролем.

WebRTC: прямые data channels, STUN `stun:stun.l.google.com:19302`, WebSocket relay при недоступности direct. Нужны WebSocket Upgrade и долгоживущие соединения. Прокси должен перезаписывать/корректно добавлять X-Forwarded-For; приложение идёт справа по цепочке доверенных точных IP. Произвольный X-Forwarded-For от прямого клиента игнорируется. TLS/HSTS, лимит соединений/трафика и интернет-DDoS находятся на прокси/провайдере.

CSP разрешает локальные scripts/Worker/WebGL/audio, inline styles интерфейса, self и явно разрешённые HTTP/WS origins. Камера, микрофон, геолокация, payment и USB не нужны. QA и debug globals отсутствуют в production build.

Лимиты: 60 join/мин/IP, 24 попытки code/мин/IP, 8 private/public/quick заявок/мин/IP, 240 join/мин/процесс, 60 WS upgrade/мин/IP. Token bucket с плавным восстановлением, максимум 4096 IP на лимит, устаревшие записи удаляются; при полном наборе новые IP получают отказ. Quick также тратит лимит создания, даже если найдена существующая комната. Четыре участника за одним IP укладываются в начальный burst. Ответ 429 содержит Retry-After: 10; это минимальная пауза, следующая попытка всё ещё может попасть под более медленный лимит. Очередь максимум 64, deadline 5 с; занятость/ожидание дают 503. Тело запроса — до 5 с, HTTP headers/request — 10 с, 512 соединений на процесс. Дополнительные ограничения прокси обязательны.

## Здоровье, идентификатор и сигналы

- `GET /health`: совместимое `{ok:true, version, rooms, maxRooms}` плюс `release:{commit,dirty}` и `draining`. Liveness остаётся 200 при ожидании завершения комнат.
- `GET /ready`: 200 только после listen и вне drain/shutdown; иначе 503, `{ok:false,release}`. Эти маршруты не выдают env, stack, токены или IP.
- Commit — полный SHA-1 Git (40 hex), встроенный в сервер; клиентский, серверный и корневой manifests совпадают. Локальные изменения помечаются `dirty:true`; production deploy такой архив отвергает. Manifest не заменяет доверенный SHA-256 архива.
- `SIGUSR2`: запретить новые join и WS upgrade, readiness 503; текущие комнаты продолжают работать. Уже выданная, но ещё не использованная резервация тоже не проходит новый WS upgrade.
- `SIGHUP`: отменить drain и вернуть readiness, если shutdown ещё не начат.
- `SIGTERM`/`SIGINT`: немедленно снять readiness/новые входы, закрыть комнаты и соединения; через 10 с принудительное завершение с ненулевым кодом. systemd/Docker должен дать минимум 15 с.
- Административного HTTP endpoint нет. Сигналы посылает ограниченный операторский механизм. Не посылать SIGUSR2 старой версии без поля `draining`: старый процесс может завершиться.

## Артефакт

Корень: `.managed-by`, `package.json`, `release.json`, `dependencies.json`, `integrity.json`, `dist/`, `dist-server/`, `node_modules/`. Runtime-зависимости включены; интерпретатор Node устанавливается и обновляется серверным мастером. `integrity.json` перечисляет SHA-256 файлов и цели внутренних symlink; архив имеет отдельный `.sha256`. Никаких `.env`, Git, QA, build tooling, установщиков, сертификатов и логов. Артефакт рассчитан на запуск в неизменяемом каталоге; приложению запись в него не требуется.
