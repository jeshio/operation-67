# Измерение вместимости VPS

Тестируются настоящие браузерные клиенты без 3D, с отдельными сессиями, игровым управлением и Worker хостов. Генератор находится в Docker на Mac, координатор — на VPS. Основная игра не заменяется. Запуск разрешён только при пустых основных комнатах; при появлении игрока нагрузка прекращается.

## Подготовка

Нужны Node.js 24, установленные зависимости проекта, Docker Desktop и доступ по SSH `jeshio@89.19.211.4`.

```sh
pnpm build
node scripts/capacity/package.mjs
ssh jeshio@89.19.211.4 'mkdir -p /tmp/roma67-capacity'
scp test-artifacts/capacity-build/*-runtime.tar.gz test-artifacts/capacity-build/*-client.tar.gz test-artifacts/capacity-build/manifest.json scripts/capacity/vps-metrics.py deploy/vps/staging.sh jeshio@89.19.211.4:/tmp/roma67-capacity/
node scripts/capacity/broker.mjs
```

Последняя команда остаётся работающей в отдельном терминале. Браузерный генератор получает доступ к измерениям через локальный посредник; SSH-ключи в контейнер не передаются. Одноразовый ключ посредника хранится в игнорируемом Git файле с правами `0600`, в отчёты не попадает.

Сборка старой версии извлекается из ревизии `fb703a6970939c86b5c67d2099065e1e0059d985`. В копии для QA меняются только потолок подключений, адрес тестового соединения и запуск через инструмент измерений. Игровой расчёт и старый протокол сохраняются. Общий QA-сценарий даёт автопилотам повышенное здоровье; тяжёлый сценарий повторяет волны 41–45. Сборки, исходная контрольная сумма, список исходников и изменения сохраняются в `test-artifacts/capacity-build/manifest.json` и соседних файлах.

## Запуск

Проверка инструментов, без вывода о вместимости:

```sh
sh scripts/capacity/run-container.sh --deploy --version current --route direct --rooms 4 --duration 20 --warmup 15 --smoke --label smoke
```

Полная серия одного маршрута или все четыре последовательно:

```sh
sh scripts/capacity/run-container.sh --suite --deploy --resume --version current --route relay
sh scripts/capacity/run-all.sh
```

Серии: старая версия; новая через сервер; новая со смешанными маршрутами; новая с прямыми маршрутами. Ступени — 4/8/16/32/64/128 комнат, затем уточнение границы с шагом две комнаты. Обычный и тяжёлый бой измеряются по пять минут после отдельного минутного прогрева. Пограничная нагрузка повторяется, предварительный лимит с запасом 25% проходит часовой прогон. Сетевая неопределённость требует отдельного повтора. Для смешанного режима предварительный лимит округляется вниз до чётного числа: иначе ровно половина трёх связей с хостом невозможна.

Полезные параметры: `--endpoint`, `--url`, `--rooms`, `--duration`, `--warmup`, `--scenarios normal,heavy`, `--seed`, `--max-rooms`, `--soak`, `--label`, `--output`, `--resume`, `--faults`. Короткий или неполный прогон не получает признак приёмочного. Возобновление учитывает сборку, контрольную сумму генератора и параметры; незавершённые ступени запускаются заново.

Для повтора после изменения внешней сети используйте отдельный каталог, например `sh scripts/capacity/run-all.sh --output test-artifacts/capacity/network-repeat`. Измерения разных условий не смешиваются. Генератор останавливается при использовании более 90% его памяти, игра или HTTPS — более 95% своего лимита либо после OOM; событие и ресурс записываются в результат.

### Проверка Mac–VPS в обход VPN

Если системный маршрут идёт через VPN, можно направить только TCP-соединения к VPS через физический интерфейс Mac. `interface-proxy.py` использует `IP_BOUND_IF`, слушает локальный адрес и разрешает только `67.jeshio.ru` / `89.19.211.4`, порты 443 и 22. Шифрование TLS и SSH остаётся между клиентом и VPS. Системные маршруты не меняются; пароль администратора не нужен.

```sh
python3 -u scripts/capacity/interface-proxy.py --interface en0 > test-artifacts/capacity/network-repeat/interface-proxy.jsonl
```

Для SSH при загрузке архивов добавьте `-o 'ProxyCommand=/usr/bin/nc -X connect -x 127.0.0.1:5299 %h %p'` и отдельный `ControlPath`, чтобы не использовать старое VPN-соединение. Посредник и генератор запускаются так (Node 24):

```sh
CAPACITY_PROXY_METRICS=test-artifacts/capacity/network-repeat/interface-proxy.jsonl CAPACITY_SSH_PROXY_PORT=5299 HTTPS_PROXY=http://127.0.0.1:5299 node --use-env-proxy scripts/capacity/broker.mjs
CAPACITY_PROXY_SERVER=http://host.docker.internal:5299 CAPACITY_NETWORK_PATH=en0-bound-connect sh scripts/capacity/run-all.sh --output test-artifacts/capacity/network-repeat
```

Маршрут записывается в конфигурацию и подпись каждой ступени. Туннель сохраняет секундные объёмы трафика, CPU и память отдельно от контейнера генератора. WebRTC не проходит через HTTP-туннель; прямые игровые каналы всё равно проверяются по доставке. При таком запуске ICMP по старому системному маршруту не используется; независимый HTTPS-запрос идёт тем же обходом. После серии остановите туннель вместе с посредником.

Полный интерфейс четырёх игроков на фоне остальных комнат, например при общем лимите 8:

```sh
sh scripts/capacity/run-container.sh --version current --route relay --rooms 8 --functional chromium --label ui-chromium
sh scripts/capacity/run-container.sh --version current --route relay --rooms 8 --functional firefox --label ui-firefox
sh scripts/capacity/run-container.sh --version current --route relay --rooms 8 --functional webkit --label ui-webkit
```

Семь комнат генерируют фон, восьмую занимает существующий сценарий полного интерфейса. Он проверяет движение, выстрелы, маршруты, повторные бои, фон, закрытие и возвращение хоста. Это отдельная функциональная проверка, не новая измеренная ступень.

## Измерения и интерпретация

Каждая секунда сохраняется в сжатый JSONL, итог ступени — в JSON, итог серии — в `*-series.json`. Подключение, прогрев, бой и внесённые сбои разделены. Процентили строятся из объединённых гистограмм исходных измерений, не усредняются между игроками. Время шага имеет разрешение 0,01 мс; остальные задержки округляются вверх до миллисекунды.

`node scripts/capacity/report.mjs` обновляет сводный `test-artifacts/capacity/REPORT.md` со ссылками на все ступени. `phaseMeasurements` в итогах содержит раздельные показатели каждого периода. Исходники всей сборки, включая новые файлы вне Git, сохраняются в `current-source.tar.gz`. Качество после массового перехода через сервер записывается отдельно в `faults[].quality`; его нельзя выдавать за качество прямого маршрута. Верхняя оценка отката учитывает возраст последнего снимка и время закрытия вкладки при шаге 60 Гц.

- Частота симуляции берётся у вычисляющего хоста, для старой версии — у сервера. Доставка снимков проверяется отдельно у каждого игрока.
- Показатель процессора — процент одного ядра. Измеряются отдельно игра, HTTPS и генератор; учитываются ограничения процессора, память и очереди.
- Трафик WebSocket включает служебные сообщения; TCP/TLS-заголовки в этот счётчик не входят. Общий трафик интерфейса VPS записывается отдельно и может включать другие службы.
- Для HTTPS дополнительно записываются TCP-очереди и повторные передачи. Адреса и порты клиентов не покидают VPS. Независимый малый HTTPS-запрос измеряет внешний канал; быстрота локального TCP-подключения через VPN за RTT не выдаётся.
- Маршруты проверяются по каналу и фактическим отправленным/полученным игровым сообщениям. Исходящий и входящий поток учитываются отдельно. Изменение доли маршрутов делает ступень непригодной для сравнения.
- Часовой прогон проверяет удерживаемую память по нижним значениям десятиминутных окон после прогрева. Сбои проверяются отдельно: переподключение, новый участник во время боя, смена хостов, возврат старых и переход через сервер. При восстановлении сравниваются очки, награды, курсор событий и состав с подтверждённой копией.

`passed` означает успех конкретного сценария; `acceptance` дополнительно требует обоих полных профилей и прогрева. Короткий smoke, полный интерфейс и ускоренные проверки не доказывают вместимость. Достигнутый потолок генератора или нестабильный интернет обозначаются отдельно от предела VPS. Результат 128 комнат без ухудшений означает нижнюю границу проверенной вместимости.

## Завершение

После выхода клиентов дождаться освобождения комнат (до 30 секунд в новой версии, до 60 в старой), затем:

```sh
ssh jeshio@89.19.211.4 'sudo bash /tmp/roma67-capacity/staging.sh down'
```

Остановить локальный посредник. Тестовая служба также имеет предельный срок жизни 24 часа, лимиты 60% ядра / 512 МБ и 64 процесса/потока. Основной службе не повышается число комнат или выделенные ресурсы. Перед возобновлением проверить пустые комнаты и заново запустить посредник.

Прямые связи внутри Docker подтверждают реальность WebRTC и нагрузку координатора. Они не измеряют долю успешного P2P между разными провайдерами. Для этого нужны отдельные проверки домашнего интернета и мобильной сети на физических устройствах.

## Физический iPhone и Mac

После завершения генератора и развёртывания текущей QA-сборки запустите на Mac, вне Docker:

```sh
node scripts/capacity/physical.mjs
```

Откроется отдельное настоящее окно Chromium и подключатся два бота без 3D. Ссылка в `test-artifacts/capacity/physical/ready.json` предназначена для четвёртого участника — iPhone в мобильной сети. Параметр `qa` отделяет тестовые настройки и рекорды от обычной игры. Ссылка открывает форму с готовым кодом; на телефоне остаётся нажать «Войти», подтвердить имя и дождаться трёхсекундного отсчёта.

Секундные состояния и действия сохраняются в папке `physical`. Для управления с компьютера можно записывать `control.json` с возрастающим целым `id` и `action`: `sleep` (все три участника Mac уходят в фон), `wake`, `relay`, `direct`, `stop`. Например, после `sleep` хостом должен стать телефон; затем `wake` возвращает компьютеру возможность принять хост при уходе Safari в фон. Для `direct` всё равно требуется реально открытый канал. Сам скрипт не подтверждает модель телефона, мобильную сеть или качество сенсорного управления — это отдельно подтверждает человек с устройством.

Если менялась только оценка уже записанных данных, `node scripts/capacity/reassess.mjs ПУТЬ_К_СТУПЕНИ.json` создаёт отдельный `.reassessed.json` с контрольной суммой анализатора. Оригинал не заменяется, незавершённый прогон не становится приёмочным. Такие пересчёты не используются автоматическим продолжением серии вместо новых запусков.
